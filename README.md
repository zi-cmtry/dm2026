# dm2026 — 电商用户行为分析

> 成都理工大学 · 大数据管理与应用
> 用真实交易数据，把「取数 → 清洗 → 入库(SQL) → 分析建模 → 可视化 → 讲结论」
> 这条链路完整走通一遍。每一段代码都要求能讲清为什么这么写。

**📄 [完整分析报告](reports/分析报告.md)** ｜ **📊 在线看板**（本地运行，见下文）

## 一句话结论

分析一家英国在线零售商的 **106 万行**真实交易数据后，得到三个核心发现：

1. **22.86% 的客户贡献了 68.82% 的营收** —— 二八法则得到验证
2. **匿名订单（无客户ID）客单价是已知客户的 2.17 倍** —— 推翻了"匿名客户价值低"的假设，
   而且这条洞察完全来自"清洗时不删数据"的决定
3. **流失预测 AUC 0.81，逻辑回归击败随机森林** —— 结构化小数据上简单模型更优

**为什么 `data/raw` 单独放且不许改？**
因为分析最怕「改完数据发现算错了，却回不到原始状态」。
`raw` 永远保持原样，所有清洗结果写到 `processed`。

## 快速开始

```bash
pip install -r requirements.txt
```

数据文件需自行下载（约 43MB，未入库）：
[UCI Online Retail II](https://archive.ics.uci.edu/dataset/502/online+retail+ii)
→ 放到 `data/raw/online_retail_II.xlsx`

```bash
# 按顺序运行（01 → 02 会慢一点，之后有 CSV 缓存就快了）
python src/01_数据探查.py
python src/02_数据清洗.py
python src/03_导入数据库.py

# 分析
python src/04_业务分析.py
python src/05_RFM用户分层.py
python src/06_留存与复购.py
python src/07_流失预测.py
python src/10_商品关联分析.py
python src/11_销量预测.py

# 看板（浏览器打开 http://localhost:8501）
streamlit run src/08_交互看板.py

# 生成答辩 PPT -> reports/汇报PPT.pptx
python src/09_生成汇报PPT.py
```

## 笔记：踩过的坑

### 环境

- **`D:\deepseek` 无法写入**：该目录所有者是 `BUILTIN\Administrators`，
  普通用户只有 `RX`（读+执行）权限。→ 项目目录一律放用户目录下。
- **`C:\` 根目录下新建的文件夹也继承只读权限**，`C:\projects\xxx` 同样写不进去。
- **git 中文乱码**：需要 `git config --global core.quotepath false`，
  否则中文文件名显示成 `\346\226\207`。
- **GitHub HTTPS 被 SNI 层阻断**：改用 SSH over 443
  （`~/.ssh/config` 里把 `github.com` 指向 `ssh.github.com:443`）。

### 数据分析

- **一行 ≠ 一笔订单**：数据粒度是商品明细行，订单数要用 `COUNT(DISTINCT Invoice)`。
- **CTE 的列名作用域**：CTE 对外只暴露它 SELECT 输出的别名。
  改过名的列，外部 JOIN 时必须用新名字（这个错我犯了两次）。
- **`np.select` 按顺序匹配**：条件优先级会改变分类结果，必须穷举所有情况。
- **左截断**：数据窗口起点那一批"首次购买"不是真首次，其留存率虚高，必须剔除。
- **数据泄漏**：站在这期做预测，就不能用下期的信息筛名单（哪怕只是筛名单）。
- **SQLite 参数不能混用**：命名参数 `:name` 和位置参数 `?` 不能出现在同一条语句里。
- **`seasonal_decompose` 按【下标】对齐序列**，不是按自然月。
  序列从 2009-12 开始时 `seasonal[0]` 是 12 月，直接用 `range(1,13)` 当标签会整体错位一格。
- **不要先写结论再看数据**：本项目有 **5 处**预写解读被数据推翻。
  结论不会报错，只会静悄悄地错。
